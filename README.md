# ADMIRAL CLUB — Telegram-бот компьютерного клуба

Полностью рабочий бот для ПК-клуба: бронирование мест по шагам, приём фото чека
об оплате, админ-панель с подтверждением/отклонением заявок и соблюдение
152-ФЗ «О персональных данных» (согласие до начала работы с ботом).

**Стек:** Python 3.10+, [aiogram 3.x](https://docs.aiogram.dev/) (Router, F, FSMContext, StatesGroup),
SQLite через [aiosqlite](https://aiosqlite.readthedocs.io/), [python-dotenv](https://saurabh-kumar.com/python-dotenv/).

## Что умеет бот

**Клиенту:**

- 🔒 Экран согласия на обработку персональных данных (152-ФЗ): пока клиент не
  нажал «✅ Я согласен», ни меню, ни бронирование недоступны.
- 💰 Прайс-лист: тарифы **Standart, VIP, S VIP, Double** и ночные пакеты (22:00–08:00).
- 📜 Правила клуба: бронирование, оплата, возвраты, поведение, оборудование.
- 🎮 Бронирование за 4 шага: тариф → время → имя → фото чека об оплате.
- 📞 Контакты администратора: текст + карточка контакта (тап — звонок).
- 🧾 Подтверждение получения чека и уведомление о решении по брони.

**Администратору:**

- 🔔 Мгновенное уведомление о новой брони: **фото чека** + тариф, время, имя,
  @username клиента и две кнопки — «✅ Подтвердить» / «❌ Отклонить».
- ✅/❌ Обработка решения: статус пишется в базу, клиенту уходит сообщение,
  в подписи чека появляется отметка о решении и времени.
- 🛠 `/admin` — статистика: всего заявок, ожидают, подтверждено, отклонено,
  число пользователей и количество согласий на обработку ПДн.
- 📋 «Активные брони» — список `pending`-заявок со страницами (по 5) и кнопками
  решения прямо в списке.
- 🛡 Защита от двойного нажатия: заявку можно подтвердить/отклонить один раз.

## Быстрый запуск за 4 шага

Требуется **Python 3.10 или новее** (проверка: `python3 --version`).

```bash
# 1. Склонировать репозиторий и перейти в него
git clone https://github.com/KingDog14/Admiral-club.git
cd Admiral-club

# 2. Создать виртуальное окружение и поставить зависимости
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 3. Настроить .env
cp .env.example .env
nano .env                          # вписать BOT_TOKEN и ADMIN_ID

# 4. Запустить
python main.py
```

Готово: напишите боту `/start` в Telegram.

Полезные флаги запуска:

| Команда                   | Что делает                                                    |
| ------------------------- | ------------------------------------------------------------- |
| `python main.py`          | запуск бота (long polling)                                     |
| `python main.py --init-db`| создать базу и применить схему, не запуская бота (токен не нужен) |
| `python main.py --version`| показать версию                                                |
| `python main.py --help`   | справка по флагам                                              |

## Где взять BOT_TOKEN и ADMIN_ID

**BOT_TOKEN**

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Придумайте имя и username бота (username должен заканчиваться на `bot`).
3. Скопируйте выданный токен вида `1234567890:AAExxxxxxxxxxxxxxxxxxxxxxxxx`
   и вставьте в `.env` строкой `BOT_TOKEN=...` — без кавычек и пробелов.
4. Если токен утёк — отзовите его у @BotFather командой `/revoke` и впишите новый.

**ADMIN_ID**

1. Напишите [@userinfobot](https://t.me/userinfobot) — он пришлёт ваш числовой `Id`.
2. Впишите его в `.env`: `ADMIN_ID=123456789`.
3. Важно: это **числовой ID**, а не `@username`. Именно этот аккаунт будет
   получать фото чеков и кнопки подтверждения.
4. Перед первым уведомлением администратор должен хотя бы раз нажать `/start`
   в диалоге с ботом — иначе Telegram не позволит боту написать ему первым.

## База данных

База создаётся **автоматически** при первом запуске бота: каталог и файл
появятся сами, схема применится из [`bot/db/schema.sql`](bot/db/schema.sql).
Отдельно «создавать базу» не нужно, но можно сделать это заранее:

```bash
python main.py --init-db
# ✅ База данных готова.
#    Файл:        /home/user/Admiral-club/data/admiral.db
#    Часовой пояс: Asia/Sakhalin
#    Таблицы:      bookings, users
#    Пользователей: 0 (согласие на ПДн: 0)
#    Заявок:        0 (ожидают: 0, подтверждено: 0, отклонено: 0)
```

Путь к файлу задаётся переменной `DB_PATH` в `.env` (по умолчанию `data/admiral.db`).
Каталог `data/` добавлен в `.gitignore` — база с персональными данными в Git не попадает.

### Схема

**users**

| Столбец         | Тип      | Описание                                        |
| --------------- | -------- | ----------------------------------------------- |
| `user_id`       | INTEGER PK | Telegram ID пользователя                      |
| `username`      | TEXT     | @username (может отсутствовать)                 |
| `first_name`    | TEXT     | имя из профиля Telegram                         |
| `consent_given` | BOOLEAN  | `1` — согласие на обработку ПДн дано (152-ФЗ)   |
| `created_at`    | DATETIME | ISO-8601 в часовом поясе клуба                  |

**bookings**

| Столбец           | Тип        | Описание                                            |
| ----------------- | ---------- | --------------------------------------------------- |
| `id`              | INTEGER PK AUTOINCREMENT | номер заявки                              |
| `user_id`         | INTEGER FK | ссылка на `users.user_id` (ON DELETE CASCADE)       |
| `tariff`          | TEXT       | `Standart` / `VIP` / `S VIP` / `Double`             |
| `time_slot`       | TEXT       | «Сейчас (с 17:51, 23.10.2026)», «На ночь (22:00–08:00)» или свой текст |
| `client_name`     | TEXT       | имя, на которое оформлена бронь                     |
| `receipt_file_id` | TEXT       | `file_id` самого большого фото чека                 |
| `status`          | TEXT       | `pending` (по умолчанию), `approved`, `rejected` + CHECK-ограничение |
| `created_at`      | DATETIME   | ISO-8601 в часовом поясе клуба                      |

Индексы: `bookings(status, id)`, `bookings(user_id, id)`, `users(consent_given)`.
Включены `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`;
все обращения к базе сериализуются через `asyncio.Lock`, поэтому параллельные
заявки не ловят «database is locked».

### Резервная копия

База — это один файл, его достаточно периодически копировать:

```bash
sqlite3 data/admiral.db ".backup '/backups/admiral-$(date +%F).db'"
# или просто: cp data/admiral.db /backups/admiral-$(date +%F).db
```

Посмотреть заявки руками:

```bash
sqlite3 data/admiral.db "SELECT id, tariff, time_slot, client_name, status, created_at FROM bookings ORDER BY id DESC LIMIT 20;"
```

## Сценарии работы

### Клиент

```
/start
  ├─ consent_given = 0 → текст про 152-ФЗ + кнопка «✅ Я согласен»
  │                       (меню и бронирование недоступны)
  └─ consent_given = 1 → приветствие + reply-меню
        ├─ 💰 Прайс-лист            → тарифы и ночные пакеты
        ├─ 📜 Правила               → правила клуба и условия брони
        ├─ 🎮 Забронировать         → FSM из 4 шагов:
        │       1. тариф (inline: Standart / VIP / S VIP / Double)
        │       2. время (inline: «Сейчас» / «На ночь (22:00–08:00)» / «Другое»)
        │          └─ «Другое» → клиент вводит время текстом
        │       3. имя (текст, 2–40 символов, только буквы)
        │       4. оплата: «Реквизиты: Сбербанк +79143618141 (Тимур В.).
        │          Оплатите и отправьте ФОТО чека сюда» → ожидание фото
        └─ 📞 Связаться с админом   → контакты + карточка контакта
```

После получения фото берётся `file_id` **самого большого** снимка, заявка
сохраняется со статусом `pending`, админу уходит чек с кнопками, а клиент
получает: «Чек получен! Ожидайте подтверждения брони (обычно 1–2 минуты)».
Если вместо фото прислали текст — бот просит прислать именно фото.

Команды клиента: `/start`, `/cancel` (прервать бронирование), `/help`, `/privacy`.

### Администратор

```
🔔 НОВАЯ БРОНЬ №7
Тариф: S VIP
Время: На ночь (22:00–08:00)
Имя: Тимур
Юзер: @username
Создана: 23.10.2026 17:51
[фото чека]
[ ✅ Подтвердить ]  [ ❌ Отклонить ]
```

- **«✅ Подтвердить»** → `status = approved`; клиенту: «✅ Ваша бронь
  подтверждена! Ждём вас в клубе. Ваше место: S VIP, На ночь (22:00–08:00)»;
  в подписи чека у админа появляется отметка «ПОДТВЕРЖДЕНО» с временем.
- **«❌ Отклонить»** → `status = rejected`; клиенту: «❌ К сожалению, мы не
  смогли подтвердить вашу бронь… Свяжитесь с админом: +7 914 361-81-41»;
  в подписи чека появляется отметка «ОТКЛОНЕНО».
- Повторное нажатие кнопки ничего не меняет — админ получает alert
  «Заявка уже обработана ранее (статус: …)».
- Если клиент заблокировал бота, решение всё равно сохранится в базе, а админ
  увидит в отметке «Клиент уведомлён: нет (клиент недоступен…)».

**`/admin`** — статистика и кнопка «📋 Активные брони»:

```
📊 Статистика
Всего заявок: 42
Ожидают: 3
Подтверждено: 35
Отклонено: 4

👥 Пользователей в базе: 28
🛡 Согласие на обработку ПДн дали: 27
```

## Что обязательно отредактировать под свой клуб

Весь контент лежит в одном файле — [`bot/texts.py`](bot/texts.py). Код трогать не нужно.

| Что                  | Где в `bot/texts.py`                          |
| -------------------- | --------------------------------------------- |
| Цены и состав тарифов | список `TARIFFS` (название, описание, пакеты 1/3/5 часов, ночная цена) |
| Название и город клуба | `CLUB_NAME`, `CLUB_CITY`                     |
| Адрес                | `CLUB_ADDRESS`                                 |
| Часы работы          | `CLUB_HOURS`                                   |
| Администратор и телефон | `ADMIN_NAME`, `ADMIN_PHONE_RAW` (для карточки контакта), `ADMIN_PHONE_PRETTY` (для текста) |
| Реквизиты оплаты     | `PAYMENT_SYSTEM`, `PAYMENT_CARD`, `PAYMENT_HOLDER` |
| Правила клуба        | шаблон `_RULES_TEMPLATE`                       |
| Текст согласия 152-ФЗ | `CONSENT_TEXT`, `PRIVACY_TEXT`                |

Прайс-лист и подсказки о цене на шаге оплаты строятся из `TARIFFS`
автоматически (`build_price_list()`, `tariff_price_hint()`), поэтому после
правки цен обновлять что-то ещё не требуется. Кнопки выбора тарифа в
бронировании тоже берутся из `TARIFFS` — можно добавить пятый тариф, и он
появится и в прайсе, и в кнопках.

Часовой пояс клуба задаётся в `.env` переменной `TZ` (по умолчанию
`Asia/Sakhalin`): от него зависят «Сейчас (с 17:51)», дата в админ-панели и
время создания заявок.

> ⚠️ В текущем прайсе стоят демонстрационные цены, а в `CLUB_ADDRESS` —
> заглушка адреса. Замените их на фактические данные клуба перед публикацией.

```
│   │   ├── reply.py           # главное меню (4 кнопки)
│   │   └── inline.py          # inline-клавиатуры + формат и парсеры callback_data

│   │   └── notifications.py   # отправка чека админу и решения клиенту (без падений)
│   ├── handlers/
│   │   ├── client.py          # клиентские сценарии (меню, прайс, правила, FSM брони)
│   │   └── admin.py           # админ-панель (статистика, список, решения)
│   └── utils/
│       ├── formatting.py      # escape_html, даты, склонения, ссылка на пользователя
│       └── telegram.py        # безопасные edit/delete/send (не роняют бота)
└── tests/
    └── smoke_test.py          # 253 проверки без интернета: БД, логика, весь сценарий
```

Разделение логики: `handlers/client.py` — клиент, `handlers/admin.py` —
админ-панель; роутер админа подключается в `main.py` **первым**, поэтому его
фильтр `IsAdmin` отрабатывает раньше клиентских хендлеров.

Формат `callback_data` (лимит Telegram 64 байта соблюдён):

| Префикс             | Назначение                       |
| ------------------- | -------------------------------- |
| `consent:give`      | согласие на обработку ПДн        |
| `bk:t:<tariff>`     | выбор тарифа (`standart`, `vip`, `svip`, `double`) |
| `bk:w:<time>`       | выбор времени (`now`, `night`, `other`) |
| `bk:cancel`         | отмена бронирования              |
| `ad:stats`          | обновить статистику              |
| `ad:list:<page>`    | страница списка активных броней  |
| `ad:ok:<booking_id>`| подтвердить бронь                |
| `ad:no:<booking_id>`| отклонить бронь                  |

## Проверка кода без запуска Telegram

В репозитории есть автономный тест — он не требует интернета и настоящего
токена, но поднимает временную базу SQLite, настоящие объекты aiogram
(`Message`, `CallbackQuery`, `FSMContext`) и подставного бота, записывающего
все исходящие сообщения:

```bash
python tests/smoke_test.py
```

Проверяется 253 условия: схема БД и все запросы, конкурентная запись, защита от
двойного подтверждения, валидация имени и времени, состав клавиатур и длина
`callback_data`, рендер всех текстовых шаблонов, работа фильтров и middleware
согласия, а также полный сценарий «/start → согласие → тариф → время → имя →
фото чека → уведомление админа → подтверждение → уведомление клиента →
повторное нажатие → отклонение → /admin».

Отдельный блок прогоняет **настоящие апдейты** через собранный `Dispatcher`
(`feed_update`) — так проверяется вся обвязка: порядок роутеров, фильтры
`IsAdmin` и `IsPrivateChat`, middleware согласия, `Command`/`StateFilter`/`F.data`
и общий FSM-контекст между сообщениями одного пользователя (включая проверку,
что в группе бот молчит, а `/admin` клиента не пускает в панель).

## Запуск в проде: systemd / screen / Docker

### systemd (рекомендуется: автоперезапуск и логи в journald)

`/etc/systemd/system/admiral-bot.service`:

```ini
[Unit]
Description=ADMIRAL CLUB Telegram bot
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=admiral
WorkingDirectory=/opt/Admiral-club
ExecStart=/opt/Admiral-club/.venv/bin/python /opt/Admiral-club/main.py
Restart=always
RestartSec=5
# .env читается самим приложением, дублировать переменные здесь не нужно

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now admiral-bot
sudo systemctl status admiral-bot
journalctl -u admiral-bot -f          # живой лог
```

```bash
screen -S admiral -dm .venv/bin/python main.py     # в фоне, вход: screen -r admiral
# или
nohup .venv/bin/python main.py >> bot.log 2>&1 &
```


## 152-ФЗ: что реализовано

- **Согласие до начала обработки.** При первом `/start` показывается текст
  согласия: оператор, состав данных, цель, перечень действий, способ обработки,
  срок действия и порядок отзыва. Пока клиент не нажал «✅ Я согласен»,
  middleware `bot/middlewares/consent.py` не пропускает его ни к одному
  сценарию — ни к меню, ни к кнопкам.
- **Фиксация согласия в базе.** Флаг `users.consent_given` + время согласия
  в логах бота; это доказательство того, что согласие было получено.
- **Минимальный состав данных.** Хранится только то, что нужно для брони:
  ID, username, имя из профиля, имя из заявки, `file_id` чека, статусы.
- **Доступ к политике в любой момент.** Команда `/privacy` работает даже без
  согласия и описывает порядок отзыва.
- **Отзыв согласия.** В базе есть `Database.revoke_consent(user_id)`
  (снимает флаг) и `Database.delete_user(user_id)` (удаляет пользователя и все
  его заявки каскадом) — вызываются по запросу клиента администратором.
- **Данные не покидают РФ и не передаются третьим лицам:** локальный файл
  SQLite на сервере клуба, доступ к заявкам — только у `ADMIN_ID`.
- **`.env` и `data/` в `.gitignore`** — токены и база не попадают в репозиторий.

Для полного соответствия также рекомендуется опубликовать политику обработки
ПДн на сайте клуба и при необходимости уведомить Роскомнадзор — это
организационные шаги, код бота им не мешает.

## Диагностика и частые ошибки

Бот пишет подробный лог в stdout (уровень задаётся `LOG_LEVEL` в `.env`):
создание заявок, решения админа, отказы доставки уведомлений.

| Симптом | Причина и решение |
| ------- | ----------------- |
| `❌ Ошибка конфигурации: Не найден BOT_TOKEN` | нет файла `.env` или в нём пустой токен: `cp .env.example .env` и заполнить |
| `ADMIN_ID должен быть числом` | вписан `@username` вместо числового ID — узнайте ID у @userinfobot |
| `Неверный BOT_TOKEN: Telegram вернул «Unauthorized»` | токен отозван или скопирован не полностью — выпустите новый у @BotFather |
| `Conflict: terminated by other getUpdates request` | запущен второй экземпляр бота — остановите его (`systemctl stop`, `ps aux \| grep main.py`) |
| `Нет связи с api.telegram.org` | нет интернета / блокирует файрвол / нужен прокси |
| Админ не получает чеки | админ ни разу не нажимал `/start` в диалоге с ботом, либо `ADMIN_ID` указан неверно |
| Бот молчит в ответ на сообщения | клиент не дал согласие на обработку ПДн — пусть нажмёт `/start` и «✅ Я согласен» |
| «Данные незаконченного бронирования не найдены» | бот перезапустили посреди сценария: черновик заявки хранится в памяти (MemoryStorage) — клиент начинает заново |
| `database is locked` | не должно возникать (WAL + лок); если появилось — проверьте, что базу не открыл сторонний процесс на запись |

## Известные ограничения

- **FSM-хранилище в памяти** (`MemoryStorage`): черновики незавершённых
  бронирований теряются при перезапуске бота. Уже созданные заявки (с чеком)
  хранятся в SQLite и никуда не девают. Если нужна устойчивость к рестартам —
  подключите Redis-хранилище (`aiogram.fsm.storage.redis.RedisStorage`) в
  `main.py` вместо `MemoryStorage()`.
- **Чеки хранятся как `file_id`**, а не как файлы на диске: это экономит место и
  соответствует ТЗ. `file_id` привязан к конкретному боту — при смене бота фото
  придётся выгружать заново.
- **Один администратор** (`ADMIN_ID`). Для нескольких админов замените сравнение
  в `bot/filters/access.py` на проверку вхождения в список ID.
- **Оплата проверяется вручную**: бот принимает фото чека, но не сверяется с
  банковским API. При желании можно добавить проверку суммы через выписку.
