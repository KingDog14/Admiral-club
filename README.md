# NOVA ARENA — Демонстрационный Telegram-бот киберспортивного клуба

Полностью рабочий демонстрационный бот вымышленного компьютерного клуба **NOVA ARENA
(г. Неополис, пр-т Кибернетиков, 42, ТЦ «Орион»)**: пошаговое бронирование мест,
приём фото чека или оплата на месте, админ-панель с подтверждением и отклонением
заявок, несколько администраторов и соблюдение 152-ФЗ «О персональных данных»
(согласие до начала работы + отзыв согласия в один тап).

Все цены, контакты, адрес и реквизиты в сборке — **100% вымышленные демо-данные**
без связи с каким-либо реальным клубом. Любое поле меняется через `.env` без
правки кода (см. [«Данные клуба»](#данные-клуба-цены-адрес-администратор)).

Для самого Telegram-бота подготовлен отдельный фирменный логотип высокого разрешения:
[`bot/assets/nova_arena_bot_logo.png`](bot/assets/nova_arena_bot_logo.png) (`2048×2048`)
и готовая версия для `@BotFather` (`/setuserpic`): [`bot/assets/avatar.jpg`](bot/assets/avatar.jpg) (`640×640`).

**Стек:** Python 3.10+, [aiogram 3.x](https://docs.aiogram.dev/) (Router, F, FSMContext, StatesGroup, `InputMediaPhoto`, `CopyTextButton`, `style`),
[Pillow](https://python-pillow.org/) (генерация HD-карточек 1280×720), SQLite через [aiosqlite](https://aiosqlite.readthedocs.io/), [python-dotenv](https://saurabh-kumar.com/python-dotenv/).

## Что умеет бот

**Графический интерфейс — один фото-экран с динамическими HD-карточками:**

- 🖼 У пользователя всегда **одно рабочее фото-сообщение** с фирменной карточкой
  клуба **1280×720** в палитре **Solar Tangerine (`#FF6224`) → Cyber Amber (`#FFB224`)
  → Supernova Mint (`#24F0A8`)** поверх абстрактных фонов и с кириллическими
  шрифтами Unbounded + Manrope + JetBrains Mono. При переходах меняются **и баннер
  раздела, и HTML-подпись, и кнопки** в том же сообщении через `editMessageMedia`,
  без спама и без code-блоков `<pre>`.
- ⚡️ **Мгновенный отклик за счёт кэша `file_id`**: сгенерированные карточки
  кэшируются в памяти и по серверному `file_id` Telegram — повторные переходы не
  загружают изображения заново.
- 🎨 **Многоцветные inline-кнопки Bot API**: на всех экранах используются
  цветовые акценты (`success` — зелёный, `primary` — синий, `danger` — красный)
  и копирование реквизитов и телефона клуба в один тап (`CopyTextButton`).
- ◀ Стек навигации: на каждом экране есть «◀ Назад» и «🏠 В меню», в «Правилах» —
  переключаемые вкладки, в мастере бронирования — визуальный индикатор шагов `1–4`,
  «‹ Шаг назад» и «✕ Отменить».
- 🛠 Кнопка **«🛠 Админ-панель»** прямо в главном меню — только у активных
  администраторов (и без лишних служебных сообщений под меню).

**Клиенту:**

- 🔒 Экран согласия на обработку персональных данных (152-ФЗ): пока клиент не
  нажал «✅ Я согласен», ни меню, ни бронирование недоступны. Отозвать согласие
  можно в любой момент — кнопкой в `/privacy`.
- 🖥 Залы и цены: визуальная таблица **Standart (16 ПК), VIP (10 ПК), S VIP
  (5 ПК), Double (2 ПК)** с пакетами 1 / 3 / 5 часов, **Утро** (8:00–13:00), **День**
  (13:00–17:00) и **Ночь** (22:00–08:00, отдельная цена в будни и в ПТ–ВС).
- ❓ FAQ inline-кнопками: список вопросов по одной кнопке, ответ открывается в
  том же сообщении с «◀ К вопросам».
- 📋 «Мои брони»: последние заявки гостя со статусами `[ ⏳ ОЖИДАЕТ ]` /
  `[ ✅ ОДОБРЕНО ]` / `[ ❌ ОТКЛОНЕНО ]`.
- 📜 Правила клуба и 📞 Контакты (кликабельный телефон, адрес, реквизиты,
  предупреждение о мошенниках).
- 🎮 Бронирование за 4 шага: зал → время → имя → **способ оплаты**
  (прислать чек или оплатить на месте, как это и делает клуб).

**Администратору:**

- 🛠 Вход в панель — кнопкой **«🛠 Админ-панель»** в главном меню (команды
  `/admin` и `/admins` оставлены как запасной вход).
- 👥 **Несколько администраторов**: заявка уходит сразу всем, решение принимает
  тот, кто нажал первым, у остальных кнопки гаснут.
- 🔔 Мгновенное уведомление о новой брони: **фото чека** (или пометка
  «оплата на месте») + тариф, время, имя, @username клиента, сумма и две кнопки
  — «✅ Подтвердить» / «❌ Отклонить».
- ✅/❌ Обработка решения: статус пишется в базу, клиенту уходит сообщение,
  в подписи чека появляется отметка о решении, времени и **кто его принял**.
- 📊 Сводка в моноширинной таблице: всего заявок, ожидают, одобрено, отклонено,
  клиенты и администраторы.
- 📋 «Активные брони» — список `pending`-заявок со страницами (по 5) и кнопками
  решения прямо в списке.
- 🧑‍💼 «Администраторы» — список и карточки персонала: добавить по ID,
  включить/отключить, сменить роль, удалить.
- 🛡 Защита от двойного нажатия и от гонки между администраторами: заявку можно
  подтвердить/отклонить ровно один раз.

## Быстрый запуск за 4 шага

Требуется **Python 3.10 или новее** (проверка: `python3 --version`).

```bash
# 1. Склонировать репозиторий и перейти в него
git clone https://github.com/KingDog14/Admiral-club.git
cd Admiral-club

# 2. Создать виртуальное окружение и поставить зависимости
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 3. Настроить .env
cp .env.example .env
nano .env                          # вписать BOT_TOKEN и ADMIN_IDS

# 4. Запустить
python main.py
```

Готово: напишите боту `/start` в Telegram.

Полезные флаги запуска:

| Команда                   | Что делает                                                    |
| ------------------------- | ------------------------------------------------------------- |
| `python main.py`          | запуск бота (long polling)                                     |
| `python main.py --init-db`| создать базу и применить схему, не запуская бота (токен не нужен) |
| `python main.py --version`| показать версию                                                |
| `python main.py --help`   | справка по флагам                                              |

## Где взять BOT_TOKEN и ADMIN_IDS

**BOT_TOKEN**

1. Откройте [@BotFather](https://t.me/BotFather) → `/newbot`.
2. Придумайте имя и username бота (username должен заканчиваться на `bot`).
3. Скопируйте выданный токен вида `1234567890:AAExxxxxxxxxxxxxxxxxxxxxxxxx`
   и вставьте в `.env` строкой `BOT_TOKEN=...` — без кавычек и пробелов.
4. Если токен утёк — отзовите его у @BotFather командой `/revoke` и впишите новый.

**ADMIN_IDS**

1. Напишите [@userinfobot](https://t.me/userinfobot) — он пришлёт ваш числовой `Id`.
2. Впишите ID в `.env` через запятую: `ADMIN_IDS=123456789,987654321`.
   Для одного администратора достаточно `ADMIN_IDS=123456789`.
3. Важно: это **числовой ID**, а не `@username`. Именно эти аккаунты будут
   получать фото чеков и кнопки подтверждения.
4. **Первый ID в списке — владелец бота**: он управляет списком
   администраторов (`/admins`) и защищён от удаления. Остальные — обычные
   администраторы: получают заявки и принимают решения.
5. Перед первым уведомлением каждый администратор должен хотя бы раз нажать
   `/start` в диалоге с ботом — иначе Telegram не позволит боту написать ему
   первым. Бот напомнит об этом в панели при добавлении.
6. Старый вариант `ADMIN_ID=123456789` (один администратор) тоже понимается —
   `ADMIN_IDS` имеет приоритет.

## База данных

База создаётся **автоматически** при первом запуске бота: каталог и файл
появятся сами, схема применится из [`bot/db/schema.sql`](bot/db/schema.sql).
Отдельно «создавать базу» не нужно, но можно сделать это заранее:

```bash
python main.py --init-db
# ✅ База данных готова.
#    Файл:        .../data/nova_demo.db
#    Часовой пояс: Europe/Moscow
#    Таблицы:      admins, booking_notifications, bookings, users
#    Пользователей: 0 (согласие на ПДн: 0)
#    Заявок:        0 (ожидают: 0, подтверждено: 0, отклонено: 0)
#    Администраторов: 0 (активных: 0)
```

Администраторы из `.env` попадают в таблицу `admins` при **первом запуске бота**
(`python main.py`) — `--init-db` только создаёт схему.

Путь к файлу задаётся переменной `DB_PATH` в `.env` (по умолчанию `data/nova_demo.db`).
Каталог `data/` добавлен в `.gitignore` — база с персональными данными в Git не попадает.

### Схема

**users**

| Столбец         | Тип      | Описание                                        |
| --------------- | -------- | ----------------------------------------------- |
| `user_id`       | INTEGER PK | Telegram ID пользователя                      |
| `username`      | TEXT     | @username (может отсутствовать)                 |
| `first_name`    | TEXT     | имя из профиля Telegram                         |
| `consent_given` | BOOLEAN  | `1` — согласие на обработку ПДн дано (152-ФЗ)   |
| `created_at`    | DATETIME | ISO-8601 в часовом поясе клуба                  |

**bookings**

| Столбец           | Тип        | Описание                                            |
| ----------------- | ---------- | --------------------------------------------------- |
| `id`              | INTEGER PK AUTOINCREMENT | номер заявки                              |
| `user_id`         | INTEGER FK | ссылка на `users.user_id` (ON DELETE CASCADE)       |
| `tariff`          | TEXT       | `Standart` / `VIP` / `S VIP` / `Double`             |
| `time_slot`       | TEXT       | «Сейчас (с 17:51, 23.10.2026)», «Ночь (22:00–08:00)», «Утро (8:00–13:00)» или свой текст |
| `client_name`     | TEXT       | имя, на которое оформлена бронь                     |
| `receipt_file_id` | TEXT       | `file_id` самого большого фото чека; `NULL` — оплата на месте |
| `status`          | TEXT       | `pending` (по умолчанию), `approved`, `rejected` + CHECK-ограничение |
| `created_at`      | DATETIME   | ISO-8601 в часовом поясе клуба                      |
| `decided_by`      | INTEGER    | кто из администраторов принял решение               |
| `decided_at`      | DATETIME   | когда решение принято                               |

**admins**

| Столбец      | Тип          | Описание                                              |
| ------------ | ------------ | ----------------------------------------------------- |
| `user_id`    | INTEGER PK   | Telegram ID администратора                            |
| `role`       | TEXT         | `owner` (владелец) или `operator` (администратор) + CHECK |
| `is_active`  | BOOLEAN      | `0` — отключён: заявки не приходят, доступа к панели нет |
| `added_by`   | INTEGER      | кто добавил (`NULL` — добавлен через `.env`)          |
| `created_at` | DATETIME     | ISO-8601 в часовом поясе клуба                        |

Намеренно **без** FOREIGN KEY на `users`: администратора можно добавить по ID
ещё до того, как он написал боту.

**booking_notifications** — копии уведомления о заявке у каждого администратора.

| Столбец      | Тип          | Описание                                              |
| ------------ | ------------ | ----------------------------------------------------- |
| `id`         | INTEGER PK AUTOINCREMENT | номер записи                              |
| `booking_id` | INTEGER FK   | заявка (`ON DELETE CASCADE`)                          |
| `admin_id`   | INTEGER      | кому отправили                                        |
| `message_id` | INTEGER      | ID сообщения в чате этого администратора              |
| `created_at` | DATETIME     | ISO-8601 в часовом поясе клуба                        |

Благодаря этим записям после решения одного администратора бот гасит кнопки у
остальных. UNIQUE `(booking_id, admin_id, message_id)` исключает дубли.

Индексы: `bookings(status, id)`, `bookings(user_id, id)`, `bookings(decided_by)`,
`users(consent_given)`, `admins(is_active)`, `booking_notifications(booking_id)`.
Включены `PRAGMA journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`;
все обращения к базе сериализуются через `asyncio.Lock`, поэтому параллельные
заявки не ловят «database is locked».

**Обновление со старой версии.** База, созданная предыдущей версией бота
(без `decided_by`/`decided_at` и без таблицы `admins`), обновляется сама при
подключении: недостающие столбцы добавляются через `ALTER TABLE`, таблицы —
через `CREATE TABLE IF NOT EXISTS`, данные не теряются
(`bot/db/database.py`, метод `_migrate()`).

### Резервная копия

База — это один файл, его достаточно периодически копировать:

```bash
sqlite3 data/nova_demo.db ".backup '/backups/nova-demo-$(date +%F).db'"
# или просто: cp data/nova_demo.db /backups/nova-demo-$(date +%F).db
```

Посмотреть заявки руками:

```bash
sqlite3 data/nova_demo.db "SELECT id, tariff, time_slot, client_name, status, created_at FROM bookings ORDER BY id DESC LIMIT 20;"
```

## Сценарии работы

### Клиент

```
/start
  ├─ consent_given = 0 → текст про 152-ФЗ + кнопка «✅ Я согласен»
  │                       (по нажатию это же сообщение превращается в меню)
  └─ consent_given = 1 → одно сообщение-экран с HUD-шапкой и inline-меню
        ├─ 🖥 Залы и цены     → моноширинные таблицы 1/3/5 ч и утро/день/ночь
        ├─ 🎮 Забронировать   → мастер из 4 шагов (‹ Шаг назад / ✕ Отменить):
        │       1. зал   (Standart / VIP / S VIP / Double)
        │       2. время («Сейчас» / «Утро» / «День» / «Ночь» / «Другое время»)
        │       3. имя   (2–40 букв; сообщение клиента удаляется, экран правится)
        │       4. оплата:
        │            • «📸 Оплатил — отправить чек» → реквизиты и ожидание ФОТО
        │            • «💵 Оплачу на месте» → заявка сразу уходит администраторам
        ├─ 📋 Мои брони       → статусы [ ⏳ ОЖИДАЕТ ] / [ ✅ ОДОБРЕНО ] / [ ❌ ОТКЛОНЕНО ]
        ├─ ❓ FAQ             → список вопросов кнопками → ответ в этом же сообщении
        ├─ 📜 Правила         → правила клуба и условия брони
        ├─ 📞 Контакты        → кликабельный телефон, адрес, реквизиты
        └─ 🛠 Админ-панель    → показывается ТОЛЬКО администраторам
```

**Когда чек обязателен.** По правилам клуба предоплата берётся **только на
ночные пакеты и только в выходные (ПТ–ВС)** — об этом сказано и в прайсе, и в
FAQ, и в правилах. Бот считает это сам по дате в часовом поясе клуба:

| Что бронируем          | Что показывает бот                                   |
| ---------------------- | ---------------------------------------------------- |
| Ночь в ПТ, СБ, ВС      | точная сумма (например **650 ₽** за Standart) и **только** кнопку «📸 Оплатил — отправить чек» |
| Ночь в будни           | сумма по будничному тарифу (550 ₽) + обе кнопки на выбор |
| Утро, День             | цена пакета + обе кнопки                              |
| «Сейчас», своё время   | «по прайсу: 120 ₽/час • 3 часа 320 ₽ • 5 часов 500 ₽» + обе кнопки |

Если гость выбрал ночь в выходные, но всё же нажал «💵 Оплачу на месте»
(например, кнопка осталась от прошлой заявки), бот покажет alert: «Ночные
пакеты в выходные (ПТ–ВС) бронируются только по полной предоплате».

После получения фото берётся `file_id` **самого большого** снимка, заявка
сохраняется со статусом `pending`, чек с кнопками уходит **всем активным
администраторам**, а клиент получает: «Чек получен! Ожидайте подтверждения брони
(обычно 1–2 минуты)». При выборе «оплачу на месте» заявка уходит администраторам
сразу и без чека — с пометкой «💵 Оплата на месте». Если вместо фото прислали
текст — бот просит прислать именно фото.

Команды клиента: `/start`, `/cancel` (прервать бронирование), `/help`, `/privacy`.

### Администратор

```
🔔 НОВАЯ БРОНЬ №7
Тариф: S VIP
Время: Ночь (22:00–08:00)
Имя: Александр
Юзер: @username
Создана: 23.10.2026 17:51
💰 К оплате: 950 ₽

📸 Чек об оплате — на фото выше. Проверьте поступление денег и выберите действие.
👥 Уведомлено администраторов: 3 — решение принимает тот, кто первым нажмёт кнопку.
[фото чека]
[ ✅ Подтвердить ]  [ ❌ Отклонить ]
```

Такую копию получает каждый активный администратор — в свой чат, со своим
`message_id`. Если гость выбрал оплату на месте, вместо строки про чек будет
«💵 Оплата на месте (предоплата не требуется). Подтвердите бронь, если место
свободно.» — кнопки решения те же.

- **«✅ Подтвердить»** → `status = approved`; клиенту: «✅ Ваша бронь
  подтверждена! Ждём вас в клубе. Ваше место: S VIP, Ночь (22:00–08:00)»;
  в подписи чека у админа появляется отметка «ПОДТВЕРЖДЕНО» с временем и именем
  того, кто принял решение.
- **«❌ Отклонить»** → `status = rejected`; клиенту: «❌ К сожалению, мы не
  смогли подтвердить вашу бронь… Свяжитесь с администратором: +7 (900) 000-42-42»;
  в подписи чека появляется отметка «ОТКЛОНЕНО».
- У **остальных** администраторов кнопки исчезают, а вместо них появляется
  отметка: «⚡️ Бронь №7 … обработана. @second_admin подтвердил её в
  23.10.2026 17:53».
- Повторное нажатие кнопки ничего не меняет — админ получает alert
  «Заявка уже обработана ранее (статус: …). Решение принял: …».
- Если два админа нажали одновременно, статус изменится один раз: запрос
  `UPDATE … WHERE status = 'pending'` атомарен, клиенту уйдёт одно решение.
- Если клиент заблокировал бота, решение всё равно сохранится в базе, а админ
  увидит в отметке «Клиент уведомлён: нет (клиент недоступен…)».

## Несколько администраторов

Администраторов может быть сколько угодно: смена днём, смена ночью, владелец
клуба и два администратора зала. Все они хранятся в таблице `admins`.

**Два способа добавить администратора**

1. **Через `.env`** (стартовый, обязательный набор):

   ```dotenv
   ADMIN_IDS=111111111,222222222,333333333
   ```

   Первый ID — **владелец** (`role = owner`), остальные — администраторы
   (`role = operator`). Список подхватывается при каждом запуске бота.

2. **Через админ-панель** (без правки файлов и перезапуска): `/admins` →
   «➕ Добавить» → отправить числовой ID одним сообщением.

```
👥 Администраторы бота — всего 3, активных 2

Владелец бота указан в .env (ADMIN_IDS) — он всегда первый и не может быть
отключён или удалён.

1. @owner — владелец, 🟢 активен
   ID: 111111111

🔒 Владелец бота задан в .env и защищён от отключения и удаления.

2. @second_admin — администратор, 🟢 активен
   ID: 222222222
   Добавил: @owner
[ ⛔️ Отключить ] [ 👑 Владелец ] [ 🗑 Удалить ]

3. Третий (ID: 333333333) — администратор, 🔴 отключён
   ID: 333333333
[ ✅ Включить ]  [ 👑 Владелец ] [ 🗑 Удалить ]

[ ➕ Добавить ] [ 🔄 Обновить ]
[ 📊 Статистика ]
```

**Кто что может**

| Действие                                        | Владелец | Администратор |
| ----------------------------------------------- | :------: | :-----------: |
| Получать новые брони и принимать решения         |    ✅    |      ✅       |
| `/admin` — статистика и активные брони           |    ✅    |      ✅       |
| `/admins` — смотреть список администраторов      |    ✅    |      ✅       |
| Добавлять, удалять, включать/отключать админов   |    ✅    |      ⛔       |
| Назначать и снимать роль владельца               |    ✅    |      ⛔       |

**Защиты, чтобы клуб не остался без управления**

- владельца из `.env` (первый `ADMIN_IDS`) нельзя удалить, отключить или
  понизить в роли — только правкой `.env`;
- нельзя удалить или отключить самого себя;
- нельзя понизить или отключить **последнего активного владельца**;
- отключённый администратор теряет доступ сразу: на `/admin` он получит
  понятное сообщение, что запись отключена и вернуть её может владелец;
- посторонний, написавший `/admin`, получает вежливый отказ и подсказку,
  как стать администратором.

**Как это работает внутри**

- Проверка доступа — фильтр `IsAdmin` (`bot/filters/access.py`): он смотрит в
  реестр `AdminRegistry` (`bot/services/admins.py`), который держит список
  активных администраторов в памяти и обновляется после каждого изменения
  (и раз в 60 секунд — на случай правок базы вручную). Поэтому добавленный
  через панель админ получает доступ **без перезапуска**.
- Рассылка заявки — `deliver_new_booking()` возвращает `DeliveryReport`:
  кому доставлено, кому нет, и пары `(admin_id, message_id)`. Они пишутся в
  `booking_notifications`.
- Решение — `set_status_if_pending(id, status, decided_by)`: атомарный
  `UPDATE … WHERE status = 'pending'`, поэтому при одновременном нажатии двух
  админов побеждает ровно один, а в базе остаётся честный `decided_by`.
- После решения `sync_peer_admins()` гасит кнопки у остальных.

> ⚠️ Telegram не позволяет боту написать пользователю первым. Новый
> администратор начнёт получать заявки только после того, как сам нажмёт
> `/start` в диалоге с ботом — панель напомнит об этом сразу после добавления.

## Данные клуба: цены, адрес, администратор

По умолчанию в боте подставлены **вымышленные демонстрационные данные клуба
«NOVA ARENA»** (без связи с реальными заведениями), так что проект готов к
показу «из коробки». Все реквизиты и контакты меняются через `.env` без правки кода.

### Параметры в `.env`

| Переменная        | Демо-значение по умолчанию                        | Зачем |
| ----------------- | ------------------------------------------------- | ----- |
| `CLUB_NAME`       | `NOVA ARENA`                                      | название в карточках и шапках |
| `CLUB_CITY`       | `Неополис`                                        | город в приветствии и политиках |
| `CLUB_ADDRESS`    | `пр-т Кибернетиков, 42 (ТЦ «Орион», 3 этаж)`      | приветствие, контакты, FAQ |
| `CLUB_HOURS`      | `круглосуточно, 24/7`                             | приветствие, контакты |
| `ADMIN_NAME`      | `Дежурный администратор (демо)`                   | контактное лицо смены в сообщениях клиенту |
| `ADMIN_PHONE`     | `+7 (900) 000-42-42`                              | контактный телефон клуба |
| `PAYMENT_SYSTEM`  | `Демо-Банк (СБП)`                                 | способ перевода предоплаты |
| `PAYMENT_CARD`    | `+7 (900) 000-77-88`                              | демо-реквизиты для предоплаты |
| `PAYMENT_HOLDER`  | `Алексей Н. (демо)`                               | получатель перевода |
| `TZ`              | `Europe/Moscow`                                   | «сейчас» в клубе, ночной пакет, даты в панели |

Как это устроено: шаблоны в `bot/texts.py` содержат плейсхолдеры
(`{club_*}`, `{admin_*}`, `{payment_*}`), а подставляет их `texts.render()` из
`bot.config.ClubInfo`. Поэтому смена администратора или реквизитов — одна
строка в `.env`, а не поиск по коду.

> ⚠️ **Администратор ≠ получатель денег.** `ADMIN_NAME` / `ADMIN_PHONE` — это
> контакт администратора смены, а `PAYMENT_*` — отдельные реквизиты предоплаты.

### Прайс-лист (вымышленные демо-тарифы)

Цены лежат в [`bot/texts.py`](bot/texts.py) в списке `TARIFFS` — это единственный
источник правды: из него собираются и прайс, и кнопки выбора тарифа, и карточки, и сумма
к оплате.

| Тариф | Зал | 1 час | 3 часа | 5 часов | Утро 8:00–13:00 | День 13:00–17:00 | Ночь 22:00–08:00 | Ночь ПТ–ВС |
| ----- | --- | ----- | ------ | ------- | --------------- | ---------------- | ---------------- | ---------- |
| **Standart** | 16 ПК | 120 ₽ | 320 ₽ | 500 ₽ | 350 ₽ | 450 ₽ | 550 ₽ | 650 ₽ |
| **VIP** | 10 ПК | 170 ₽ | 460 ₽ | 700 ₽ | 480 ₽ | 620 ₽ | 750 ₽ | 850 ₽ |
| **S VIP** | 5 ПК | 230 ₽ | 620 ₽ | 950 ₽ | 650 ₽ | 800 ₽ | 980 ₽ | 1100 ₽ |
| **Double** | парная комната (2 ПК) | 280 ₽ | 750 ₽ | 1150 ₽ | 780 ₽ | 950 ₽ | 1150 ₽ | 1300 ₽ |

Чтобы поменять цену, достаточно поправить одну строку в `TARIFFS`:

```python
Tariff(
    key="standart",
    title="Standart",
    emoji="🟢",
    pcs=16,
    hour1=120, hour3=320, hour5=500,
    morning=350, day=450,
    night=550, night_weekend=650,
    description="Общий зал, 16 ПК",
),
```

После правки обновлять что-то ещё не нужно: `build_price_list()`,
`tariff_price_hint()` и `amount_due()` считают всё сами. Добавьте пятый тариф —
он появится и в прайсе, и в кнопках бронирования.

Остальные тексты (правила, FAQ, согласие 152-ФЗ) лежат там же, в `bot/texts.py`:
`_RULES_TEMPLATE`, `FAQ_ITEMS`, `CONSENT_TEXT`, `PRIVACY_TEXT`.

Часовой пояс клуба задаётся в `.env` переменной `TZ` (по умолчанию
`Europe/Moscow`): от него зависят «Сейчас (с 17:51)», дата в админ-панели и
время создания заявок.

В репозитории есть автономный тест — он не требует интернета и настоящего

Проверяется 625 условий: схема БД и все запросы, конкурентная запись, защита от

Отдельные блоки проверяют:

  клиенту и возврат доступа той же кнопкой;
- **нескольких администраторов**: разбор `ADMIN_IDS` (разделители, дубликаты,

- **обновление базы прошлой версии** (`ALTER TABLE` для `decided_by`/`decided_at`

Отдельный блок прогоняет **настоящие апдейты** через собранный `Dispatcher`

## 152-ФЗ: что реализовано

- **Согласие до начала обработки.** При первом `/start` показывается текст
  согласия: оператор, состав данных, цель, перечень действий, способ обработки,
  срок действия и порядок отзыва. Пока клиент не нажал «✅ Я согласен»,
  middleware `bot/middlewares/consent.py` не пропускает его ни к одному
  сценарию — ни к меню, ни к кнопкам.
- **Фиксация согласия в базе.** Флаг `users.consent_given` + время согласия
  в логах бота; это доказательство того, что согласие было получено.
- **Минимальный состав данных.** Хранится только то, что нужно для брони:
  ID, username, имя из профиля, имя из заявки, `file_id` чека, статусы.
- **Доступ к политике в любой момент.** Команда `/privacy` работает даже без
  согласия.
- **Отзыв согласия в один тап (реализовано).** В `/privacy` есть кнопка
  «🚫 Отозвать согласие» → бот предупреждает, что перестанет работать →
  подтверждение «✅ Да, отозвать» / «↩️ Отмена» → флаг `users.consent_given`
  снимается, кэш middleware очищается, и клиент видит: «Согласие отозвано,
  обработка прекращена». После этого меню, прайс, правила, FAQ и бронирование
  недоступны — ровно как требует ч. 2 ст. 9 152-ФЗ. Вернуть доступ можно той же
  кнопкой «✅ Я согласен» или `/start`.
  Полное удаление данных — через администратора: в базе есть
  `Database.revoke_consent(user_id)` и `Database.delete_user(user_id)`
  (удаляет пользователя и его заявки каскадом).
- **Данные не покидают РФ и не передаются третьим лицам:** локальный файл
  SQLite на сервере клуба, доступ к заявкам — только у администраторов из
  таблицы `admins` (список задаёт владелец клуба).
- **`.env` и `data/` в `.gitignore`** — токены и база не попадают в репозиторий.

Для полного соответствия также рекомендуется опубликовать политику обработки
ПДн на сайте клуба и при необходимости уведомить Роскомнадзор — это
организационные шаги, код бота им не мешает.

## Диагностика и частые ошибки

Бот пишет подробный лог в stdout (уровень задаётся `LOG_LEVEL` в `.env`):
создание заявок, решения админа, отказы доставки уведомлений.

| Симптом | Причина и решение |
| ------- | ----------------- |
| `❌ Ошибка конфигурации: Не найден BOT_TOKEN` | нет файла `.env` или в нём пустой токен: `cp .env.example .env` и заполнить |
| `ADMIN_IDS: «@nickname» не похоже на числовой Telegram ID` | вписан `@username` вместо числового ID — узнайте ID у @userinfobot |
| `Не найден ADMIN_IDS` | в `.env` нет ни `ADMIN_IDS`, ни устаревшего `ADMIN_ID` |
| `Неверный BOT_TOKEN: Telegram вернул «Unauthorized»` | токен отозван или скопирован не полностью — выпустите новый у @BotFather |
| `Conflict: terminated by other getUpdates request` | запущен второй экземпляр бота — остановите его (`systemctl stop`, `ps aux \| grep main.py`) |
| `Нет связи с api.telegram.org` | нет интернета / блокирует файрвол / нужен прокси |
| Админ не получает чеки | админ ни разу не нажимал `/start` в диалоге с ботом, либо его ID указан неверно |
| Новый админ не видит панель | владелец не добавил его через `/admins`, либо он отключён (статус «🔴 отключён») |
| Клиент отозвал согласие и бот «сломался» | так и задумано: обработка ПДн прекращена. Вернуть доступ — `/start` → «✅ Я согласен» |
| Клиент не может оплатить на месте ночь в субботу | по правилам клуба ночные пакеты в ПТ–ВС — только по полной предоплате; это не ошибка |
| В текстах бота старый адрес/телефон | поправьте `CLUB_ADDRESS`, `ADMIN_NAME`, `ADMIN_PHONE`, `PAYMENT_*` в `.env` и перезапустите бота |
| В логе `Заявка №N сохранена, но администраторы не заданы` | в базе нет активных админов и `ADMIN_IDS` пуст — добавьте администратора |
| Заявку подтвердил не тот админ | так и задумано: решает тот, кто нажал первым, остальные видят отметку об этом |
| Бот молчит в ответ на сообщения | клиент не дал согласие на обработку ПДн — пусть нажмёт `/start` и «✅ Я согласен» |
| «Данные незаконченного бронирования не найдены» | бот перезапустили посреди сценария: черновик заявки хранится в памяти (MemoryStorage) — клиент начинает заново |
| `database is locked` | не должно возникать (WAL + лок); если появилось — проверьте, что базу не открыл сторонний процесс на запись |

## Известные ограничения

- **FSM-хранилище в памяти** (`MemoryStorage`): черновики незавершённых
  бронирований теряются при перезапуске бота. Уже созданные заявки (с чеком)
  хранятся в SQLite и никуда не девают. Если нужна устойчивость к рестартам —
  подключите Redis-хранилище (`aiogram.fsm.storage.redis.RedisStorage`) в
  `main.py` вместо `MemoryStorage()`.
- **Чеки хранятся как `file_id`**, а не как файлы на диске: это экономит место и
  соответствует ТЗ. `file_id` привязан к конкретному боту — при смене бота фото
  придётся выгружать заново.
- **Владелец задаётся в `.env`.** Первый ID в `ADMIN_IDS` защищён от удаления и
  понижения — это страховка от ситуации «все админы удалены, панель недоступна».
  Назначить дополнительного владельца можно кнопкой «👑 Владелец» в `/admins`,
  но сменить основного — только правкой `.env` и перезапуском.
- **Список администраторов из `.env` перечитывается при старте**: отключённый
  через панель администратор, который остался в `ADMIN_IDS`, при следующем
  запуске включится снова. Чтобы убрать человека окончательно — удалите его и
  из `ADMIN_IDS` тоже.
- **Оплата проверяется вручную**: бот принимает фото чека, но не сверяется с
  банковским API. При желании можно добавить проверку суммы через выписку.
- **Предоплата считается по дате клуба**, а не по факту: правило «ночь в ПТ–ВС —
  по полной предоплате» бот применяет по дню недели в часовом поясе `TZ`. Если
  клуб меняет правило (например, добавляет предоплату на праздники), правка —
  одна функция `prepayment_required()` в `bot/texts.py`.
